# 通过从机 Harness 调用 Codex

简体中文 | [English](CODEX.en.md)

Codex 由目标设备的 Harness 本地 sub agent/工具调用，没有独立 Codex Worker。主机增加调用选择和会话检索策略，不改变从机协议；已绑定从机无需重新安装或配对，但需要本地工具支持真实 Codex 会话的查询、运行状态核对和按编号恢复。

| 用户意图 | 选择与行为 |
| --- | --- |
| 普通 Codex 任务 | `single`：独立任务，新建并保存原生对话，不复用最近会话 |
| 明确新建对话 | `new`：新建并保存，不使用 `--ephemeral` |
| 查找、列出历史会话 | `search`：只读检索，不执行续写 |
| 继续之前、已有或正在执行的任务 | `continue`：先查相关 Hub 任务，再由从机检索本地原生会话 |

主 Agent 可用 `agent_hub_tasks_search` 按关键词、设备、项目、任务编号或原生 Session ID 查询相关任务；`agent_hub_dispatch` 的可选 `codex` 参数提供 `mode`（默认 `auto`）、`query`、`project_path`、`task_id` 和 `session_id`。上下文指向 Codex 时，即使新一句没有写 Codex，主 Agent 也应显式提供该参数。明确指定模式优先于自动文本分类。

例如通过微信说：

- “让开发机用 Codex 修复 alpha 项目的测试。” → 独立保存的新任务。
- “继续开发机之前 alpha 项目的 Codex 任务，补上导出功能。” → 先查相关任务及原生会话，再决定续写。
- “看看刚才那个 Codex 任务还在执行吗？” → 主 Agent 查询已有任务，不重复启动。
- “列出开发机之前的 Codex 会话。” → 只读检索，不能据此自动续写。

相关任务正在执行时返回 `wait`；等待审批或输入时返回 `interaction_required`；执行状态不确定时返回 `needs_reconciliation`。此时不创建重复执行任务，也不打断已有轮次。

续写检索只返回真实会话编号、标题、项目绝对目录、更新时间、原生运行状态和匹配原因。只有唯一匹配、目录相符且确认空闲，主机才原子地创建关联续写任务。从机执行前还需再次确认空闲，并按明确编号恢复；不能用 `--last`，恢复失败不能静默新建。多个候选请用户选择；无匹配、状态未知、能力缺失、绑定变更或设备离线时停止并说明原因。引用已完成任务可带回原会话和项目线索，仍需重新检索核对。

`agent_hub_task` 返回检索任务的 `codex_resolution` 和 `followup_task`。检索完成不代表用户目标完成；成功检索属于内部阶段，不单独推送微信。最终执行结果仍先由主机 AI 总结，再统一投递一次。原检索编号可以取消关联后续任务；已取消的检索即使晚到结果也不会再触发续写。

本地工具提供原生编号时保存任务与会话元数据，以便后续查找；不上传完整对话、思考或原始命令输出。工具不提供编号时标记 `codex_tracking=unavailable`，不能宣称已有可恢复绑定。测试使用模拟 Codex 适配器验证完整任务链，真实会话查询/恢复能力由各设备本地 Harness 工具提供；没有能力时明确报告，不编造会话。
